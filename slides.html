01 / 核心概念

為什麼需要 RAG？從「閉書考」到「開書考」

傳統 LLM（如未連網的對話模型）僅依賴訓練時的參數記憶，面對新資訊或私有文件時容易產生「幻覺（一本正經胡說八道）」。

❌ 傳統 LLM：閉書考試

  • 知識停留在訓練截止日期
  • 不知道公司內部文件或個人筆記
  • 忘記細節時容易自行腦補（幻覺）

✅ RAG 架構：開書考試

  • 回答前先翻閱外部最新知識庫
  • 可隨時抽換、更新參考文件
  • 答案有所本，大幅降低胡說八道

02 / 運作全景

RAG 運作的三大階段

RAG 並非單一模型，而是一條「先建索引、再檢索、最後生成」的資料管線（Pipeline）：

1. 索引 (Indexing)

文件切塊 → 轉成向量 → 存入向量資料庫（離線準備）

➔

2. 檢索 (Retrieval)

問題轉向量 → 計算語意相似度 → 撈出前 K 筆段落

➔

3. 生成 (Generation)

問題 + 參考段落組成 Prompt → LLM 產出精準回答

💡 核心精神：把「記憶知識」交給資料庫，讓 LLM 專注發揮「閱讀理解與語言組織」的強項。

03 / 關鍵技術一

文本切分（Chunking）：為什麼不能整本書塞進去？

動輒數萬字的 PDF 若整份丟給模型，不僅超出長度上限，更會讓關鍵資訊淹沒在雜訊中。

遞迴字元切分（Recursive Splitting）

優先依照段落（\n\n）→ 換行（\n）→ 句號切分，確保每一小塊（Chunk）都保有完整的語意，不會把一句話硬生生腰斬。

重疊視窗（Chunk Overlap）

相鄰兩塊保留 10%～20% 重疊（例如每塊 500 字、重疊 50 字）。這樣即使重點剛好落在切分邊界，也能在下一塊完整保留上下文。
